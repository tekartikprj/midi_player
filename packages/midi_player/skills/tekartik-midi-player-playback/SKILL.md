# Midi playback (tekartik_midi_player)

`tekartik_midi_player` is a small Flutter plugin that plays midi **files** on
Android and iOS through a `MethodChannel`, with a Dart-only fallback on Linux
that shells out to `timidity` or `wildmidi`. It plays files from disk; it does
not parse, build or synthesize midi (use `tekartik_midi` to write a file
first).

## Guidelines

* Git dependency (`publish_to: none`, not on pub.dev):
  ```yaml
  dependencies:
    tekartik_midi_player:
      git:
        url: https://github.com/tekartikprj/midi_player
        path: packages/midi_player
  ```
  This is the maintained package. A package with the **same name** exists in
  the `tekartikprj/milomedy` repo, whose library is annotated `@Deprecated` and
  points here; if a project still depends on that one, switch the `url` and
  drop the `// ignore: deprecated_member_use` comments (see the skill
  `tekartik-midi-player-setup`).
* One import: `package:tekartik_midi_player/midi_player.dart`. Everything else
  (`MidiPlayerPlugin`, `midiPlayerPlugin`, the method-name constants, the
  `linuxPlayMidiFile*` helpers) lives under `lib/src/` - do not import it.
* Platforms: the pubspec declares only the legacy android plugin
  (`androidPackage: com.tekartik.tekartik_midi_player.plugin`,
  `pluginClass: MidiPlayerPlugin`) plus the iOS podspec. Android and iOS
  implement every method; **Linux** only supports `playFile` (pure Dart, via
  `process_run` running `timidity`, else `wildmidi` - install one with
  `sudo apt install timidity`). macOS and Windows raise
  `MissingPluginException`, and the library imports `dart:io`, so it does not
  build for web at all.
* iOS: the `sounds.sf2` sound font ships in the pod resources, but as the
  README says you must also add `sounds.sf2` as an asset in Xcode (drop it in
  the Flutter/Runner section, added as a link), otherwise playback is silent.
* One-shot playback: `await playFile(path)` loads, plays, waits for the native
  `onComplete` and closes the player. On Linux it runs the external player and
  returns when that process exits. It never returns early, so do not use it for
  a track the user may want to pause.
* Controlled playback: create players **only** with the top-level
  `loadFile(path)`. It returns a `Player` registered in the plugin's player
  map, which is what makes its `onComplete` stream fire; a bare `Player()` or
  the `newPlayer` getter is unregistered and never completes. Then use
  `resume()` (that is "play"), `pause()`, `seekTo(millis)`, `getDuration()`,
  `getCurrentPosition()` (both in milliseconds and `null` when the player is
  not `ready`), `isPlaying()` and `close()`.
* `Player.ready` is `loaded && !closed`. Calling `Player.loadFile` twice on the
  same instance throws `StateError` - load a new player instead. `close()` is
  idempotent and safe to call from `dispose()`; always close, and close the
  previous player before loading the next one.
* Paths are native file paths, never asset keys or urls: copy a bundled asset
  (`rootBundle.load`) or generated bytes to a real file (`path_provider` +
  `dart:io`) first, as the example app does.
* `MidiPlayer.platformVersion` is the plugin smoke test.
  `MidiPlayer.setDebugModeOn([on])` turns on native logging;
  `MidiPlayer.getDebugModeOn()` only reflects the deprecated
  `devSetDebugModeOn` helper, so do not rely on it. `MidiPlayer.loadData(bytes)`
  sends a `load` call that no native side implements - write the bytes to a
  file and use `loadFile` instead. `mainPlayer` is a lazy `MidiPlayer`
  singleton kept for convenience.
* Testing: the package has no `test/` - it needs a device. The runnable
  reference is `example/midi_player_example`, a `tekartik_test_menu_flutter`
  menu app covering platform version, load / resume / pause / seek / duration
  / position and a 5 second play. In widget tests, mock the
  `'tekartik_midi_player'` channel (last example) rather than expecting real
  playback.
* Android project files under `android/` are regenerated by
  `dart run tool/delete_and_create_android_project.dart` (it deletes and
  re-runs `flutter create --template plugin`); do not hand-edit the generated
  gradle files, and re-apply the plugin sources afterwards.

## Examples

### Play a bundled midi asset once

```dart
import 'dart:io';

import 'package:flutter/services.dart';
import 'package:path/path.dart';
import 'package:path_provider/path_provider.dart';
import 'package:tekartik_midi_player/midi_player.dart';

/// Copies an asset to a real file, the only thing the plugin can play.
Future<String> copyAssetToFile(String assetPath, String fileName) async {
  var data = await rootBundle.load(assetPath);
  var bytes = data.buffer.asUint8List(data.offsetInBytes, data.lengthInBytes);
  var dir = await getApplicationDocumentsDirectory();
  var filePath = join(dir.path, fileName);
  await File(filePath).writeAsBytes(bytes, flush: true);
  return filePath;
}

Future<void> playPop() async {
  var filePath = await copyAssetToFile(join('assets', 'pop.mid'), 'pop.mid');
  // Returns when playback is over (or when timidity exits on linux).
  await playFile(filePath);
}
```

### Controlled playback, with a single live player

```dart
import 'dart:async';

import 'package:tekartik_midi_player/midi_player.dart';

class MidiPlayback {
  Player? _player;
  StreamSubscription<bool>? _subscription;

  /// Loads [path], replacing any previously loaded file.
  Future<void> load(String path, {void Function()? onComplete}) async {
    await stop();
    // Only loadFile() registers the player, so onComplete can fire.
    var player = _player = await loadFile(path);
    _subscription = player.onComplete.listen((_) => onComplete?.call());
  }

  Future<void> play() async => _player?.resume();

  Future<void> pause() async => _player?.pause();

  /// Position and duration are milliseconds, null while not ready.
  Future<int?> position() async => _player?.getCurrentPosition();

  Future<int?> duration() async => _player?.getDuration();

  Future<bool> playing() async => (await _player?.isPlaying()) ?? false;

  Future<void> seek(int millis) async => _player?.seekTo(millis);

  /// Safe to call from dispose(); close() is idempotent.
  Future<void> stop() async {
    await _subscription?.cancel();
    _subscription = null;
    await _player?.close();
    _player = null;
  }
}
```

### Plugin smoke test

```dart
import 'package:flutter/services.dart';
import 'package:tekartik_midi_player/midi_player.dart';

Future<String> midiPlayerStatus() async {
  try {
    await MidiPlayer.setDebugModeOn();
    return await MidiPlayer.platformVersion ?? 'unknown';
  } on MissingPluginException {
    // No native implementation (macOS, Windows...).
    return 'unsupported';
  }
}
```

### Mock the channel in a widget test

The channel name is `'tekartik_midi_player'`. Player ids are handed out by the
plugin starting at 1 and incremented for every `Player` created in the process,
so a test that fakes `onComplete` must send the id it expects.

```dart
import 'package:flutter/services.dart';
import 'package:flutter_test/flutter_test.dart';
import 'package:tekartik_midi_player/midi_player.dart';

void main() {
  TestWidgetsFlutterBinding.ensureInitialized();
  const channel = MethodChannel('tekartik_midi_player');
  var messenger = TestDefaultBinaryMessengerBinding.instance.defaultBinaryMessenger;
  var calls = <String>[];

  setUp(() {
    calls.clear();
    messenger.setMockMethodCallHandler(channel, (call) async {
      calls.add(call.method);
      switch (call.method) {
        case 'duration':
          return <String, dynamic>{'millis': 1000};
        case 'playing':
          return <String, dynamic>{'playing': true};
      }
      return null;
    });
  });
  tearDown(() => messenger.setMockMethodCallHandler(channel, null));

  test('load and play', () async {
    var player = await loadFile('/tmp/test.mid');
    await player.resume();
    expect(await player.getDuration(), 1000);
    expect(await player.isPlaying(), isTrue);
    await player.close();
    expect(calls, contains('loadFile'));
    expect(calls, contains('resume'));
  });
}
```
